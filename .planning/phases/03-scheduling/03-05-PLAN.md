<objective>
Fix scheduling model: scheduledFor is a property, not a status.

**Problem:** Current implementation treats "scheduled" as a status that replaces "approved". This is wrong because:
1. A draft can be created with a scheduled date but still need approval
2. "Agendado" is WHEN to publish, not WHERE in the approval flow

**Fix:** Remove "scheduled" as status. Use only scheduledFor field as an orthogonal property.
</objective>

1. Remove the status validation that requires 'approved'
2. Allow scheduling for 'pending' OR 'approved' drafts (not rejected/published)
3. Do NOT change the status - only set scheduledFor
4. Add an unschedule capability (allow setting scheduledFor to undefined)

Updated mutation:
```typescript
export const schedule = mutation({
  args: {
    id: v.id('drafts'),
    scheduledFor: v.optional(v.number()), // optional allows unscheduling
  },
  handler: async (ctx, args) => {
    const draft = await ctx.db.get(args.id)
    if (!draft) throw new Error('Draft not found')
    if (draft.status === 'rejected' || draft.status === 'published') {
      throw new Error('Cannot schedule rejected or published drafts')
    }

    await ctx.db.patch(args.id, {
      scheduledFor: args.scheduledFor, // undefined to unschedule
      updatedAt: Date.now(),
    })
    return args.id
  },
})
```
