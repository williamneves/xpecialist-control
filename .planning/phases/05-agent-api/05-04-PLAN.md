  <action>
Add a GET /api/openapi.json endpoint that returns the OpenAPI spec.

Two approaches (choose based on what works better):

Option A - Static spec (simpler):
Create an inline OpenAPI 3.0 spec object documenting all endpoints:
```typescript
const openApiSpec = {
  openapi: "3.0.3",
  info: {
    title: "Xpecialist Control API",
    version: "1.0.0",
    description: "API for AI agents to manage tweet drafts"
  },
  servers: [{ url: "/api/v1" }],
  components: {
    securitySchemes: {
      bearerAuth: {
        type: "http",
        scheme: "bearer",
        description: "API token in format xpc_XXXXXXXX_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
      }
    },
    schemas: {
      Draft: { type: "object", properties: {...} },
      Error: { type: "object", properties: { error: { type: "string" } } }
    }
  },
  security: [{ bearerAuth: [] }],
  paths: {
    "/drafts": {
      get: { summary: "List drafts", ... },
      post: { summary: "Create draft", ... }
    },
    "/drafts/{id}": { ... },
    "/drafts/{id}/approve": { ... },
    "/drafts/{id}/reject": { ... },
    "/drafts/{id}/schedule": { ... },
    "/drafts/{id}/publish": { ... },
    "/tokens": { ... },
    "/tokens/{prefix}": { ... }
  }
};

app.get("/api/openapi.json", (c) => c.json(openApiSpec));
```

Option B - Use convex-helpers CLI (if available):
```bash
npx convex-helpers open-api-spec
```
Then serve the generated file.

Document each endpoint with:
- Summary and description
- Request body schema (for POST endpoints)
- Response schema
- Required permissions in description
- Possible error responses (401, 403, 400, 404)

This endpoint does NOT require authentication (public spec).

<task type="checkpoint:human-verify" gate="blocking">
  <what-built>Complete Agent API: token authentication, draft endpoints, token management UI, OpenAPI spec</what-built>
  <how-to-verify>
Test the complete workflow:

1. **Create token via UI:**
   - Go to /settings/api-tokens
   - Create token with permissions: drafts:read, drafts:create, drafts:approve
   - Copy the token (will be shown only once)

2. **Test API authentication:**
   ```bash
   # Should fail (no auth)
   curl -i YOUR_CONVEX_URL/api/v1/drafts
   # Expected: 401 Unauthorized

   # Should succeed (with auth)
   curl -H "Authorization: Bearer YOUR_TOKEN" YOUR_CONVEX_URL/api/v1/drafts
   # Expected: 200 with { drafts: [...] }
   ```

3. **Create draft via API:**
   ```bash
   curl -X POST \
     -H "Authorization: Bearer YOUR_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"content":"Test draft from API agent"}' \
     YOUR_CONVEX_URL/api/v1/drafts
   # Expected: 201 with { id: "..." }
   ```

4. **Verify draft appears in UI:**
   - Go to main dashboard
   - New draft should appear in pending tab

5. **Approve via API:**
   ```bash
   curl -X POST \
     -H "Authorization: Bearer YOUR_TOKEN" \
     YOUR_CONVEX_URL/api/v1/drafts/DRAFT_ID/approve
   # Expected: 200 with { success: true }
   ```

6. **Test permission denial:**
   - Create new token with only drafts:read permission
   ```bash
   curl -X POST \
     -H "Authorization: Bearer NEW_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"content":"Should fail"}' \
     YOUR_CONVEX_URL/api/v1/drafts
   # Expected: 403 Forbidden
   ```

7. **Test token revocation:**
   - Revoke a token via UI
   - Try to use it
   # Expected: 401 Unauthorized

8. **Check OpenAPI spec:**
   ```bash
   curl YOUR_CONVEX_URL/api/openapi.json | head -20
   ```
   - Should return valid JSON spec
   - Optionally paste into swagger editor to visualize

Expected results:
- All authenticated requests with valid token succeed
- Missing/invalid tokens return 401
- Insufficient permissions return 403
- Token management UI works end-to-end
- OpenAPI spec is valid and complete
